# Vectra — резервная одометрия трамвая по модели (ROS 2 Humble)

Команда Vectra, хакатон «Московский транспорт», кейс «Резервная одометрия по модели».

- Трамвай без GNSS и IMU. Нода получает скорости двух тележек (км/ч) и позицию ручки контроллера (−15…+15).
- Нода публикует скорость `/result/velocity` и положение `/result/position` с частотой 20 Гц. Метки времени берутся из bag.
- Модель внутри: физическая модель вагона (таблица привода по реальным записям) и фильтр UKF. Показания тележек проверяются на правдоподобие, так ловятся юз, буксование и отказы датчиков. Положение ведётся по карте путей с привязкой к остановкам.
- GNSS используется только в первые 3 с для начальной выставки. Дальше на выход он не влияет, это проверено.
- Все числа ниже посчитаны на 15 чистых отложенных записях против GNSS. Рядом всегда стоит наивная база «только колесо».

## Быстрый старт

**Docker (одна команда).** Нужны Docker с Compose v2 и папка с прогонами (rosbag2).

```bash
git clone https://github.com/kitay-sudo/vectra-tram-odometry.git && cd vectra-tram-odometry
cp .env.example .env            # DATA_DIR — папка с прогонами, BAG — какой проиграть
docker compose up --build       # нода + ros2 bag play + проба задержки + мост + страница http://localhost:8080
docker compose run --rm test    # colcon build + тесты, без сети
```

**Без Docker, чистый ROS 2 Humble.** Интернет и `rosdep` не нужны.

```bash
source /opt/ros/humble/setup.bash
mkdir -p ~/vectra_ws/src && cp -r vectra-tram-odometry/ros2_ws/src/* ~/vectra_ws/src/
cd ~/vectra_ws && colcon build && source install/setup.bash

# терминал 1: сначала нода
ros2 launch tram_state_estimator tram.launch.py
# терминал 2 (тоже source install/setup.bash): потом bag, с задержкой 3 с
ros2 bag play <путь к прогону> -d 3
```

Подробно, с проверкой задержки, частоты, CPU и RAM, — [docs/JURY.md](docs/JURY.md).

## Топики

| Топик | Тип | Что |
|---|---|---|
| `/vehicle/front_bogie_velocity`, `/vehicle/rear_bogie_velocity` | `tram_vehicle_msgs/VelocitySensor` | вход: скорость тележки, км/ч (подтвердили организаторы) |
| `/vehicle/driver_position_cmd` | `tram_vehicle_msgs/DriverControllerCommand` | вход: позиция ручки −15…+15 |
| `/sensing/gnss/{master,rover}/fix` | `sensor_msgs/NavSatFix` | вход, **только** окно выставки: 3 с от первой точки |
| `/result/velocity` | `tram_vehicle_msgs/VelocitySensor` | выход: продольная скорость, м/с, 20 Гц |
| `/result/position` | `nav_msgs/Odometry` | выход: x, y, z точки `base_link` в MGRS от угла квадрата 37UCB (непрерывно), z — высота рельса; σ в ковариациях; 20 Гц |
| `/result/acceleration` | `geometry_msgs/AccelStamped` | выход: ускорение модели, м/с² |
| `/tram/estimator_status` | `tram_msgs/EstimatorStatus` | диагностика: режим, σ, сцепление μ, срыв, «стоим или скользим», шум показаний, `valid` |

Система координат выхода и как её поменять параметром — [docs/JURY.md §4](docs/JURY.md#4-система-координат-положения).

## Главные числа

15 чистых отложенных записей (`tools/split.json: holdout_scored`, около 80 км пути).
Лист параметров и карта для этих чисел собраны только по обучающим записям.
Эталон скорости — GNSS master. Эталон положения — точка `base_link` по двум
антеннам, в MGRS от 37UCB, как у судьи. Источник — [docs/EVAL.md](docs/EVAL.md).

| Метрика | Модель | Только колесо |
|---|---:|---:|
| скорость, MAE, м/с | **0,0362** | 0,0462 |
| скорость, RMSE, м/с | **0,0917** | 0,0947 |
| смещение скорости, м/с | **+0,0037** | +0,0064 |
| смещение на торможении, м/с | **+0,0049** | +0,0475 |
| истина внутри ±2σ скорости | **94,7 %** | — |
| положение, средняя 3D-ошибка, м | 3,99 | 3,97 |
| ошибка в конце прогона, ср. / медиана, м | 11,8 / 2,33 | 11,7 / 2,34 |
| дрейф по концу, % пути, медиана / макс | 0,044 / 1,00 | 0,050 / 1,00 |
| поперёк оси pathgraph организаторов, ср., м | 0,011 | 0,011 |
| шагов без положения после выставки | 0 | 0 |

На чистых записях положение у модели и у базы одинаковое: его держат карта путей и
привязка к остановкам, а не модель. Модель выигрывает по скорости, особенно на
торможении, и при отказах датчиков. Отказы вносились в 3 отложенные реальные записи
([docs/EVAL.md §6](docs/EVAL.md#6-инъекции-аномалий)):

| Аномалия | Модель: MAE, м/с; остаток пути | Только колесо |
|---|---:|---:|
| отказ передней тележки (0 км/ч, 60 с) | **0,028; 0,1 м** | 2,379; 186,3 м |
| обе тележки 0 км/ч, 20 с | **1,001; 36,1 м** | 9,328; 206,8 м |
| юз −30 % обеих тележек на торможении | **0,182** | 1,772 |
| буксование +30 % обеих на разгоне | **0,211** | 0,861 |
| шум ×5 | **0,100** | 0,146 |
| выбросы ×3 | **0,034** | 0,213 |

Реальное время: полный bag 20 мин, скорость проигрывания 1x, нода в контейнере с
лимитами ТЗ `--cpus 2 --memory 512m` ([docs/audit/INTEGRATION.md](docs/audit/INTEGRATION.md#r23-проверка-итоговое-дерево-integration2)):

| Требование ТЗ | Измерено |
|---|---|
| ≥ 10 Гц | 20,0 Гц, 24 117 из 24 117 узлов сетки |
| задержка вход → выход ≤ 100 мс, пик ≤ 250 мс | p50 50,9 мс, p99 53,9 мс, max 173,5 мс; больше 250 мс — 0 из 46 023 |
| ≤ 2 ядра CPU | в среднем 0,101 ядра, максимум 0,18 |
| ≤ 0,5 ГБ ОЗУ, без утечек | 68,7 МБ, рост 0,0 МБ/мин |
| `colcon build` без интернета | 3 пакета за 12,3 с в чистом `ros:humble-ros-base` |

Задержка около 50 мс заложена схемой: нода шагает по сетке 50 мс, и показание
попадает в следующий узел.

## Чем наше решение отличается

Каждый пункт можно проверить одной командой. Числа взяты из
[docs/EVAL.md](docs/EVAL.md), [docs/audit/INTEGRATION.md](docs/audit/INTEGRATION.md)
и [docs/SANDBOX.md](docs/SANDBOX.md). Сценарий показа —
[docs/DEMO.md](docs/DEMO.md).

1. **Параметры подогнаны по реальным записям, а не взяты из паспорта.**
   Из данных получены таблица привода A(u, v) (31 позиция ручки × 11 скоростей),
   запаздывание 0,2 с, инерция 0,3 с, масштаб колёс, шумы и выходная σ. Лист для
   отчёта собран только по обучающим записям.
   `docker compose run --rm eval --variants` → [EVAL §4](docs/EVAL.md#4-заглушки-крипа-против-подогнанных--нулевых):
   с подогнанным листом MAE 0,0362 м/с, с паспортными заглушками крипа 0,0403.
2. **Честная неопределённость.** Нода публикует σ скорости и положения, и эта σ
   откалибрована. Смещение скорости по фазам малое: от −0,013 до +0,017 м/с.
   `docker compose run --rm eval` → [EVAL §3.1](docs/EVAL.md#31-скорость): истина
   внутри ±2σ скорости 94,7 % времени (стоянка 96 %, тяга 94 %, выбег 94 %,
   торможение 95 %). Для положения |ошибка вдоль пути| ≤ 2σ в 92,4 % времени.
3. **Устойчивость к аномалиям.** 12 видов аномалий вносятся в реальные записи.
   Для каждой считается ошибка до, во время и после. Нода выставляет флаги
   `slip`, `slip_all`, `ambiguous`, `valid` и выдаёт оценку сцепления μ. На NaN и
   разрывах времени нода не падает.
   `docker compose run --rm eval` → [EVAL §6](docs/EVAL.md#6-инъекции-аномалий):
   юз обеих тележек −30 % даёт MAE 0,182 м/с против 1,772 у колёс, флаг срыва
   стоит 99 % окна. В ROS: `IMAGE=vectra/tram:compose tools/ros_e2e.sh --bag 30618_bab2fe58 --inject "nan --at 15 --dur 3" --build` —
   нода жива, 1180 выходов из 1180.
4. **Реальное время в числах.**
   `tools/measure_realtime.sh --bag 30618_e9a34502 --cpus 2 --memory 512m --build` →
   20 мин без вмешательства: 20,0 Гц, p99 53,9 мс, 0,101 ядра, 68,7 МБ, утечки нет.
5. **Воспроизводимость.** Docker-образ закреплён по digest. Сборка идёт без сети.
   Оценка детерминирована: `tools/eval.py --check-determinism` сравнивает два прогона
   побайтно.
   `docker compose run --rm test` → colcon build и 262 теста без сети.
6. **Наивная база рядом везде.** Каждая таблица оценки, каждый прогон в симуляторе и
   каждая аномалия считаются и для «только колеса». База проходит через ту же связку,
   ту же карту и ту же выставку.
   `docker compose run --rm eval` → MAE скорости 0,0362 против 0,0462 м/с; смещение на
   торможении +0,0049 против +0,0475.
7. **Объяснимость.** На каждом шаге видно, что решила модель: режим, сколько тележек
   принято и сколько отвергнуто, срыв и его знак, «стоим или скользим», шум показаний,
   μ. В симуляторе это же видно в панели «Что сейчас думает модель» простыми словами.
   `ros2 topic echo /tram/estimator_status` показывает эти поля на каждом шаге. При юзе
   −30 % в оценке флаг срыва стоит 99 % окна, а достоверной оценка помечена только
   24 % окна ([EVAL §6](docs/EVAL.md#6-инъекции-аномалий)).
8. **Честные ограничения.** Слабые места описаны с числами, а не спрятаны:
   [MODEL.md §9](MODEL.md#9-ограничения), [docs/SANDBOX.md §6](docs/SANDBOX.md#6-слабые-места-что-честно-ответить-если-спросят).
   `simulator/index.html?mode=sandbox&preset=both_fail_start` → если обе тележки
   отказали сразу после трогания, модель 20 с считает, что вагон стоит, и ошибается
   до 10,8 м/с.
9. **Симулятор.** Страница работает без сети. В ней три режима. «Песочница»
   считается ядром пакета, перенесённым в JavaScript. «Прогон данных комиссии» —
   реальная отложенная запись, которую считает сам пакет. «Живой ROS 2» показывает
   ноду через rosbridge.
   `IMAGE=vectra/tram:compose bash js-port/check.sh` (нужны Node.js и кэш записи
   `30618_e9a34502` в `analysis/cache` — его строит `docker compose run --rm eval --quick`;
   см. [js-port/README.md](js-port/README.md)) → JS-порт совпадает с Python-пакетом
   до 1,5·10⁻¹² м/с на каждом шаге.

## Карта репозитория

```
ros2_ws/src/                    пакеты ROS 2 Humble (их собирает colcon)
  tram_vehicle_msgs/            сообщения кейса; в манифесте добавлен <maintainer>, без него colcon в Humble падает
  tram_msgs/                    EstimatorStatus — диагностика оценщика
  tram_state_estimator/         нода tram_estimator (Python)
    tram_state_estimator/
      estimator_core.py         модель вагона + UKF, срывы и отказы (без ROS)
      runner.py                 связка: сетка 50 мс по меткам, выставка, положение по карте
      track_map.py, geodesy.py  карта путей; MGRS/UTM
      body.py                   точка base_link по антеннам
      tram_node.py              нода: подписки, публикация, проверка входов, пульс
    config/tram.yaml            лист жюри (генерируется tools/gen_params.py)
    config/track_map.npz        карта путей жюри
    config/eval/                лист и карта ОЦЕНКИ (только обучающие записи)
    launch/tram.launch.py       запуск по ТЗ (respawn)
    test/                       тесты пакета (pytest)
analysis/                       калибровка (calib_*.py, calib_all.sh), карта (build_map.py)
tools/                          eval.py (оценка), inject.py (аномалии), split.json,
                                ros_smoke.sh, ros_e2e.sh, measure_realtime.sh, ros_probe.py, export_replay.py
simulator/                      страница: песочница, прогон данных комиссии, живой ROS 2
js-port/                        JS-порт ядра и связки, сверка с Python (check.sh)
prototype/                      стенд имитатора: сценарии, опознавание параметров
docker/, docker-compose.yml     образ, compose: демо, test, eval, server
docs/                           документы (таблица выше)
```

Данные кейса (rosbag2), кэш анализа и pathgraph организаторов в репозиторий не
входят.
