# Симулятор Vectra (simulator/index.html)

Одна страница: песочница на настоящей модели пакета и прогон реальных записей. Работает с
`file://` без сети: CSS собран статически, шрифты системные. Числа сценариев собраны в
[docs/SANDBOX.md](../docs/SANDBOX.md), сверка переноса модели в браузер - в
[js-port/README.md](../js-port/README.md).

Команды выполняются из корня репозитория в bash (Linux, macOS, Git Bash). В Git Bash перед
`docker run` с путями `-v` нужен `MSYS_NO_PATHCONV=1`. `<repo>` - полный путь к клону.

## 1. Режимы

В шапке два режима. Режим можно задать и адресом: `?mode=sandbox` или `?mode=replay`.

| Режим | Что показывает | Откуда числа |
|---|---|---|
| Песочница | сцена с вагоном, табло, график, карта, сценарии | модель пакета в браузере, имитатор или настоящая запись |
| Прогон данных комиссии | реальная отложенная запись: скорость, ошибки, план, состояние | сам пакет: `tools/export_replay.py` |
| Живой ROS 2 | тот же экран по живому потоку ноды | rosbridge, 10 Гц на топик |

Живой ROS 2 по умолчанию скрыт: кнопка в шапке появляется с `?live=1`, а `?mode=live` сразу
открывает режим.

## 2. Песочница

Модель в песочнице настоящая: это `estimator_core.py` и шаг связки `Runner`, перенесённые в
JavaScript (`js/est.js`, `js/runner.js`). С Python они совпадают до 1,5·10⁻¹² м/с
(`js-port/check.sh`). Параметры - лист жюри `config/tram.yaml` (`js/sheet.js`).

- **Что получает модель.** Только сообщения тележек и ручки, как нода. GNSS в песочнице
  модель не получает: скорость и путь от него не зависят.
- **Имитатор.** Трамвай, погода и отказы датчиков придуманы (`js/plant.js`). Две тележки в
  7,55 м, сцепление каждой по её месту на линии, колёса буксуют и юзят, защита от юза,
  уклон по профилю pathgraph, датчики как в записях: км/ч, около 9,35 раза в секунду.
- **Линия.** `js/track.js` - pathgraph организаторов, оба направления, остановки из карты
  пакета. Без файла песочница работает на линии-заглушке и подписывает это.
- **Сценарии.** Список в строке «Сценарий»: настоящие данные, свободная поездка, ручное
  управление, погода и сцепление, отказы датчиков, подъём и застройка. Переключатели, которые
  задаёт выбранный сценарий, на это время заблокированы.
- **Старт и конец.** Все сценарии на линии пакета начинаются с первой остановки. Через 3 с
  после конца сценария и после показа 60 с вагон встаёт на первую остановку и ждёт команды,
  а окно «Метрики» показывает итог законченного сценария. Шаги показа 60 с сменяются без
  затемнения: сцена доезжает до нового места за доли секунды.
- **«Модель думает».** Строка над графиком: каким тележкам модель верит и почему. Кнопка
  «подробнее» раскрывает решения по тележкам, режим, сцепление, разброс и то, что на самом
  деле происходит в имитаторе.
- **Значки шапки.** «Как устроена модель», «Метрики», «Показ 60 с» (главные сценарии подряд,
  в конце метрики), «Как читать экран», день и ночь. Окна «Пакет ROS 2» и «Запись поездки»
  скрыты, их код на месте.

Параметры адреса:

| Параметр | Что делает |
|---|---|
| `preset=<ключ>` | сценарий сразу: `free` (по умолчанию), `jury`, `rec`, `dry`, `rain_spin`, `ice_skid`, `leaves`, `front_fail`, `both_fail`, `both_fail_start`, `both_fail_stop`, `stuck`, `dropout`, `noise`, `rush`, `hill`, `urban`, `manual` |
| `seed=<число>` | зерно имитатора, по умолчанию 7, как в таблице `docs/SANDBOX.md` |
| `sbsp=1`, `4` или `10` | скорость времени |

## 3. Настоящие данные в песочнице

Группа «Настоящие данные» выделена цветом: здесь вместо имитатора проигрывается настоящая
запись вагона 30618. Модель получает её сообщения тележек и ручки в том порядке, как их
получает нода. Файл записи (около 1 МБ) загружается при первом выборе сценария.

| Сценарий | Запись | Истина |
|---|---|---|
| Проверка жюри | `30618_88aea4d9` из проверки организаторов, 22 мин | эталон организаторов `/localization/kinematic_state` |
| Запись датасета | `30618_e9a34502`, та же, что в прогоне данных комиссии, 20 мин | GNSS master этой записи |

- **Сдвиг выхода, как у ноды.** В «Проверке жюри» модель сверяется с эталоном с
  `speed_output_delay_s` из листа (0,08 с), как нода под проверкой организаторов. RMSE
  скорости в песочнице 0,042 м/с, у ноды под их проверкой 0,0418 м/с. Против GNSS сдвиг не
  применяется.
- **Линия и стоянки записи.** Сцена, карта и профиль высот строятся по пути самой записи,
  вместе с разворотными кольцами, которых нет в pathgraph. Стоянки стоят там, где вагон
  стоял дольше 2,5 с: платформы и светофоры, подпись «Стоянка N».
- **Окно «Метрики».** Показывает MAE и RMSE скорости модели и простого среднего колёс.

## 4. Прогон данных комиссии

Страница проигрывает файл прогона `replays/*.js`: его пишет `tools/export_replay.py`, гоняя
`Runner` пакета по записи так же, как нода. От 1100 пикселей в ширину экран помещается в одно
окно: графики, состояние с метриками и план в три колонки.

- **Эталон скорости.** |v| GNSS master, пары с выходом не дальше 0,05 с.
- **Эталон положения.** base_link по паре антенн master и rover, та же точка вагона, что на
  выходе `Runner`.
- **GNSS в модели.** Только первые 3 с для выставки, дальше он только эталон.
- **Пояснения.** Длинные подписи карточек открываются значком «i» в заголовке.

Выгрузить прогон `30618_e9a34502` с пятью вариантами (около 5 мин).

```bash
docker run --rm --cpus 2 -v <repo>:/repo -v <repo>/data:/repo/data:ro \
  -v <repo>/analysis/cache:/repo/analysis/cache:ro -w /repo vectra/tram:compose \
  python3 tools/export_replay.py
```

| Опция | Что делает |
|---|---|
| `--run <прогон>` | другой прогон из `holdout_scored` (`tools/split.json`) |
| `--allow-train` | разрешить обучающий прогон |
| `--variants <список>` | варианты через запятую: `clean`, `front_zero`, `both_zero`, `dropout`, `skid_brake` |
| `--sheet eval`, `jury` или `<путь>` | лист, по умолчанию `eval`, по правилам `tools/eval.py` |
| `--map <файл>` | карта путей, по умолчанию только из обучающих прогонов; `''` - без карты |

## 5. Живой ROS 2

Адрес моста берётся по порядку: `?ros=`, адрес из поля на странице, `config.js`, по
умолчанию. По умолчанию страница с `https://хост` идёт на `wss://хост/ros`, с `file://` и
localhost - на `ws://localhost:9090`.

Запустить ноду и мост на ноутбуке, затем открыть `index.html?mode=live`.

```bash
docker run --rm -p 127.0.0.1:9090:9090 -v <repo>:/repo:ro -v <data>:/data:ro -e BAG=30618_e9a34502 vectra/tram:compose bash /repo/simulator/deploy/live_demo.sh
```

Поднять на сервере с доменом страницу и мост за Caddy с TLS.

```bash
DOMAIN=<домен> DATA_DIR=<папка записей> docker compose -f simulator/deploy/compose.demo.yml up -d
```

- **Мост только для чтения.** Подписка лишь на топики страницы, публикация и
  `set_parameters` закрыты (`deploy/live_demo.sh`). Отладка без ограничений:
  `ROSBRIDGE_OPEN=1`.
- **Свой прокси.** `deploy/nginx.conf`: страница и `location /ros` с заголовками Upgrade.
- **Точка эталона.** Страница выбирает base_link или антенну master по первым 10 парам и
  пишет выбор под планом; `?ref=base_link` или `?ref=master` задаёт явно.

## 6. Пересборка файлов данных

Собрать лист песочницы `js/sheet.js` из `config/tram.yaml`.

```bash
docker run --rm -v <repo>:/repo -w /repo vectra/tram:compose python3 js-port/gen_sheet.py
```

Собрать линию `js/track.js` из pathgraph организаторов (`_incoming/pathgraph`, в git не
лежит).

```bash
docker run --rm -v <repo>:/repo -w /repo vectra/tram:compose python3 simulator/tools/gen_track.py
```

Скопировать перенос модели `js/est.js` и `js/runner.js` из `js-port/`.

```bash
node js-port/sync.js
```

Выгрузить запись датасета для песочницы из кэша `analysis/cache`.

```bash
docker run --rm -v <repo>:/repo -w /repo vectra/tram:compose python3 simulator/tools/gen_record.py 30618_e9a34502
```

Выгрузить запись проверки организаторов из её папки.

```bash
docker run --rm -v <repo>:/repo -w /repo vectra/tram:compose python3 simulator/tools/gen_record.py --bag _incoming/check/check-code/bags/30618_88aea4d9
```

Пересчитать сценарии и записать сводку в `docs/SANDBOX.md`.

```bash
node simulator/test/sandbox_report.js --write
```

## 7. Проверки

| Проверка | Что проверяет |
|---|---|
| сценарии без браузера | все сценарии, сводка и `test/sandbox_report.json`, зерно 7 |
| перенос модели | JS против Python, обязательно после любой правки `estimator_core.py` |
| страница в Chromium | 0 исключений, метрики сценариев и прогонов, окна, телефон, живой режим с имитатором моста |
| живой режим | настоящий rosbridge, обрыв и переподключение, мост только для чтения |

Пересчитать сценарии без записи в `docs/`.

```bash
node simulator/test/sandbox_report.js
```

Сверить перенос модели с пакетом (код выхода 0 - совпадает).

```bash
bash js-port/check.sh
```

Собрать образ проверки страницы.

```bash
docker build -t vectra/tram:sim simulator/test
```

Проверить страницу в Chromium без сети, скриншоты лягут в `<out>`.

```bash
docker run --rm --network none -v <repo>/simulator:/sim:ro -v <out>:/out vectra/tram:sim node /sim/test/page_test.js
```

Проверить живой режим против настоящего rosbridge.

```bash
bash simulator/test/live_test.sh
```

Пересобрать CSS после правки классов Tailwind.

```bash
bash simulator/css/build_css.sh
```

## 8. Ограничения

- **Имитатор - приближение.** Погода, сцепление и защита от юза подобраны на глаз, числа
  песочницы на отказах - лучший случай. Реальные числа - в прогоне данных комиссии и в
  [docs/EVAL.md](../docs/EVAL.md).
- **Песочница не делает части работы ноды.** Нет онлайн-поправки масштаба колёс по остановкам
  (в пределах ±3 %) и положения на карте с поправкой по GNSS. Скорость и путь модели те же.
- **Против эталона организаторов колесо ближе.** На записи жюри RMSE скорости простого
  среднего колёс 0,030 м/с, у модели 0,042 м/с. Против GNSS на записи датасета наоборот: MAE
  модели 0,020 м/с, у колеса 0,032 м/с.
