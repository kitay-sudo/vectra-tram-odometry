# JS-порт ядра и связки (оценщик песочницы)

`est.js` повторяет `estimator_core.py` пакета: ядро `684530832766` (коммит `3466ac4`,
со срывом обеих тележек разом и оценкой шума показаний). `runner.js` повторяет ту часть
`Runner` (`runner.py`), которую видит ядро. Песочница (`simulator/`) считает оценку
этими файлами с листом жюри `config/tram.yaml`.

| Файл | Что это |
|---|---|
| `est.js` | порт `estimator_core.py`; список перенесённых функций — в заголовке файла |
| `runner.js` | порт шага `Runner`: сетка по меткам (узлы кратны dt), свежесть показаний по тележкам, `wheel_timeout` → разомкнутый режим, `handle_timeout`, приведение показания к моменту шага, ускорение выхода, σ пути (`position_sigma`) и база «только колесо» (`NaiveCore` из `tools/eval_replay.py`). Не перенесены своя база времени (сбросы, провалы, очередь) и положение — сверка проверяет, что на записи эти ветки не сработали |
| `gen_sheet.py` | лист для песочницы `simulator/js/sheet.js` из листа пакета, так же, как его читает нода (`tools/export_replay.resolve_sheet`) |
| `sync.js` | копии `est.js`, `runner.js` → `simulator/js/` (байт в байт) |
| `record.py` + `compare.js` | сверка ядра на 15 сценариях `prototype/scenarios.py` (Params по умолчанию: 4 оси × 2 датчика, рад/с) |
| `record_bag.py` + `compare_bag.js` | сверка ядра на реальной записи, лист жюри (2 тележки, км/ч, табличный привод, 20 Гц), входы `core.step` так, как их подаёт `Runner`; варианты с аномалиями из `tools/inject.py` и формы срыва из `tools/slip_study.py` (EDGE); кроме чисел сверяются режим, неоднозначность, срыв и срыв всех осей и печатается, сколько шагов шёл срыв всех осей (покрытие новых веток) |
| `record_runner.py` + `compare_runner.js` | сверка связки: те же сообщения тележек и ручки → JS `Runner` против Python `Runner` на каждом шаге сетки, плюс база «только колесо» |
| `gnss_check.py` | GNSS после выставки не влияет на выход: запись через Python `Runner` (лист жюри, карта пакета) с GNSS на весь прогон, без GNSS и с GNSS только первые 3 с |
| `check.sh` | всё вместе одной командой |

## Отпечаток ядра

`TramEst.PORT` в `est.js` указывает ядро, с которым порт сверен: `core_sha1` — это
sha1 `estimator_core.py` с переводами строк LF, 12 знаков. Тот же отпечаток пишут
`tools/export_replay.py` (в `simulator/replays/index.js`), `gen_sheet.py` (в
`simulator/js/sheet.js`) и `record*.py`. Если прогоны комиссии или лист посчитаны другим
ядром, страница сама подписывает песочницу «упрощённое ядро» и убирает утверждение о
совпадении. `compare*.js` при другом отпечатке завершаются с кодом 1.

## Если ядро поменялось

1. Перенести правку в `est.js`. Затронутые места — по списку «ЗЕРКАЛО» в заголовке
   файла; если правка в шаге `Runner` — в `runner.js`.
2. `bash js-port/check.sh`. Если сверка зелёная, а сменился только отпечаток,
   обновить `PORT` в `est.js`.
3. `node js-port/sync.js`. Если менялся лист — ещё `python3 js-port/gen_sheet.py`
   в образе.
4. `node simulator/test/sandbox_report.js --write` — таблица `docs/SANDBOX.md`,
   затем `simulator/test/page_test.js`.

Для песочницы в `est.js` есть `Estimator.diag()` (в ядре его нет): запись решения
фильтра по каждой оси — принята, по согласию, буксование, юз, скачок, после срыва,
«стоим или скользим», выброс — и причины исключения датчика. Запись только читает
состояние, на числа не влияет: `compare.js` и `compare_bag.js` сверяют порт без записи,
`compare_runner.js` — с записью, как в песочнице.
