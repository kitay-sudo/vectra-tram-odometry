# Датасет: разбор записей

Источник всех чисел — [`tools/data_audit.py`](../tools/data_audit.py) (rosbags 0.10.9, образ `vectra/tram:compose`):

```
docker run --rm -v <репозиторий>:/repo -v <папка с записями>:/repo/data:ro -w /repo \
  vectra/tram:compose python3 tools/data_audit.py --workers 6
```

Сырые выходы лежат в `out/data/`: `bags.csv` (прогон × ~190 колонок), `topics.csv` (прогон × топик),
`pairs.csv` (дубликаты), `summary.json` (агрегаты), `bags_table.md`, `routes.png`, `handle_hist.png`.
Каталог `out/` в git не входит; таблицы по записям и дублям лежат в репозитории как [`docs/data/bags.csv`](data/bags.csv) и [`docs/data/pairs.csv`](data/pairs.csv).
Скрипт детерминирован: два прогона (6 и 4 процесса) дали побайтно одинаковые `bags.csv`, `topics.csv`, `pairs.csv`, `summary.json`, `bags_table.md`.
Время полного прогона около 4,5 мин на 6 процессах.

Обозначения: «уник.» — 97 уникальных записей (дубли выброшены); F/R — передняя/задняя тележка;
«метка» — `header.stamp`; «запись» — время записи в bag; «смещение» — запись − метка.
Координаты: плоские ENU (м) от 55.80484N 37.42050E, как в `analysis/build_map.py`.

### 2.2. Метки времени

* `header.stamp` заполнены везде: 0 нулевых, 0 повторов подряд. Внутри топика метки монотонны, кроме сбоев ±1 с (п. 8 сводки).
* В sqlite строки лежат по возрастанию времени записи. Исключение — одна строка в 7 bag (5 уник.) на участках сбоев.
* Хвост буфера на старте (п. 7). Пример `30618_0e41eac3`: первое сообщение (rear) имеет смещение 3,53 с, ручка 3,44, fix 2,22, rover vel 0,63. Нормальный режим (смещение < 0,1 с) наступает через ~0,13 с записи.
* Сбои ±1 с не похожи на гонку sec/nanosec: сдвинутые метки идут по всей секунде (мс 31…935). Похоже на ступеньку часов источника, которая держится от 1 до сотен секунд.
* Для ноды: `ros2 bag play` публикует в порядке записи. Значит, нода увидит и хвост буфера, и сбои (п. 7–9 сводки).

* дубль — `= хэш` оригинала;
* split — первое разбиение (`sorted(ids)[2::5]`, `val` — отложенные);

* едет к 10 с — скорость > 0,3 м/с в первые 10 с (в первые 3 с не едет никто);

## 4. Дубликаты и утечка в обучение

**Метод.** Для каждого bag считается sha1 по всем сообщениям 7 топиков (топик + время записи + сырые байты CDR) и отдельно по потокам трёх входов.
Для поиска частичных копий: 64-битные хэши каждого сообщения передней тележки, пересечение множеств у всех пар одного вагона, плюс пересечение интервалов записи.

## 6. Вопросы к организаторам и ответы

| Вопрос | Ответ и что сделано |
|---|---|
| По какой шкале времени судья сопоставляет выход с эталоном? | По `header.stamp`, ближайшая метка в пределах ~0,05 с ([DATASET_README.md](DATASET_README.md), [TZ_REQUIREMENTS.md](TZ_REQUIREMENTS.md)); выход штампуется метками входов |
| По какой антенне эталон, какое начало системы координат, как считается `z`? | Плоские MGRS от угла квадрата 37UCB непрерывно, точка `base_link` по tf антенн, `z` — уровень рельса, ошибка по x, y, z ([ORGANIZER_ANSWERS.md](ORGANIZER_ANSWERS.md)) |
| Проверочные записи — с той же линии и тех же вагонов? | Организаторы прислали pathgraph этой линии; проверка — только на вагоне 30618; даты записей неизвестны |
| Скорость тележек в проверочных данных тоже в км/ч? | Да, подтверждено |
| «GNSS гарантирован первые секунды» — что дальше? | Посреди маршрута сообщения могут быть, но редко; их можно использовать для коррекции (`gnss_correction`) |
| Допустима ли карта путей из GNSS обучающих записей? | Да |
| Известно ли о 25 дублях и 35 записях без GNSS? | Ответа нет; дубли исключены из разбиения (`tools/split.json`) |
| Почему часть троганий идёт при тормозной позиции ручки? | Ответа нет; согласие тележек сильнее модели ([MODEL.md](../MODEL.md) §0.3) |

Решения по двум вопросам к команде: сдвиг «карта − GNSS» из окна выставки в
выходе не держится (`keep_offset_max_status: -1`, на обучающих записях выигрыша
нет); масштаб колёс уточняется онлайн по остановкам (`wheel_scale_online`,
[VEHICLES.md](VEHICLES.md) §6).
