# Учёт различий трамваев

Организаторы (26.09, 18:05): проверять будут **только вагон 30618**, а учёт
различий трамваев засчитают в плюс. Здесь - чем отличаются вагоны 30618 и 30639
и их записи разных дней, что из этого нода учитывает и сколько это даёт.

## 1. Коротко

- Вагоны отличаются **масштабом колёс**: сколько км/ч показывают датчики тележек
  при той же скорости по GNSS. По всем данным 30639 «спешит» на 0,38 %
  относительно 30618.
- **У одного вагона масштаб меняется по датам сильнее, чем между вагонами:**
  30618 3 сентября - на 1,1 % против июля-августа, 30639 5 мая - на 1,1 % против
  26 августа. Причину данные не называют (возможно, износ или обточка колёс).
- Таблица привода (какое ускорение даёт ручка) у вагонов практически одна:
  отдельная таблица для 30618 ничего не даёт (раздел 4).
- Нода получила два параметра:
  - **`vehicle`**: `30618` (по умолчанию, для жюри), `30639` или `auto`.
    Известный вагон - берётся его масштаб колёс, `auto` - общий лист по обоим
    вагонам (как было до этой правки, совпадает бит в бит);
  - **`wheel_scale_online`** (по умолчанию включён): масштаб колёс уточняется
    на ходу по привязкам к остановкам - так нода справляется со сменой масштаба
    по датам, которую заранее не знает (раздел 6).
- **Что это дало.** На обучающих записях 30618 (46 записей, выбор настроек -
  только по ним): MAE скорости −4 %, на «чужой» дате 03.09 - −22 %, на
  остальных датах без изменений. На отложенных: у 30639 MAE −20 % (0,0762 →
  0,0610 м/с), у 30618 +1,9 % (0,0261 → 0,0266 м/с) - из-за одной записи из 12
  (раздел 5). Положение параметры почти не меняют: у 30618 ±0,01 м.

## 2. Что различается: масштаб колёс

Масштаб колёс `meas_scale` - поправка к показаниям тележек: скорость GNSS,
делённая на среднее двух тележек, на ровном ходу (скорость больше 3 м/с,
ускорение меньше 0,1 м/с², тележки согласны). Считается по всем записям с GNSS,
медиана по всем отсчётам (`analysis/calib_vehicle.py`).

| вагон | дата | записей с GNSS | `meas_scale` | к общему |
|---|---|---:|---:|---:|
| 30618 | 27.07 | 26 | 1,00076 | −0,03 % |
| 30618 | 10.08 | 10 | 1,00147 | +0,04 % |
| 30618 | 26.08 | 12 | 1,00123 | +0,01 % |
| 30618 | **03.09** | 4 | **1,01256** | **+1,15 %** |
| 30639 | **05.05** | 9 | **0,99244** | **−0,86 %** |
| 30639 | 26.08 | 8 | 1,00380 | +0,27 % |
| **30618** | все | 52 | **1,00136** | +0,03 % |
| **30639** | все | 17 | **0,99757** | −0,35 % |
| оба | все | 69 | 1,00109 | - |

Что видно:

- 30618 весь июль и август стабилен (разброс ±0,04 %), и общий лист почти
  совпадает с ним: в данных 52 записи 30618 против 17 у 30639.
- В один день (26.08) вагоны отличаются на 0,26 %. Это и есть «разница трамваев».
- Смена даты у одного вагона даёт 1,1-1,2 %. Ошибка масштаба 1 % - это 1 % пути:
  около 54 м на 5,4 км линии, если бы не было привязки к остановкам.

## 3. Параметры `vehicle` и `wheel_scale_online`

В листе `config/tram.yaml` (его делает `ros2_ws/src/tram_state_estimator/tools/gen_params.py` из калибровки):

```yaml
vehicle: "30618"                          # 30618 | 30639 | auto
vehicle_ids: ["30618", "30639"]
vehicle_meas_scale: [1.001362, 0.997575]  # лист жюри: все записи вагона
wheel_scale_online: true                  # онлайн-масштаб колёс (раздел 6)
```

| значение `vehicle` | что делает нода |
|---|---|
| `30618` (по умолчанию) | `meas_scale` = 1,001362 - по всем записям 30618 |
| `30639` | `meas_scale` = 0,997575 - по всем записям 30639 |
| `auto` | общий лист как есть: `meas_scale` 1,001093 по обоим вагонам |
| что-то другое | как `auto`, в логе предупреждение «вагон … неизвестен» |

Обе онлайн-подстройки по привязкам к остановкам работают при любом значении
`vehicle`: масштаб пути для положения (`scale_adapt`, была и раньше) и масштаб
колёс для скорости (`wheel_scale_online`, новая). Для `auto` это и есть
подстройка под вагон «на ходу».

Как задать:

```bash
ros2 launch tram_state_estimator tram.launch.py vehicle:=30639
ros2 run tram_state_estimator tram_estimator --ros-args -p vehicle:=auto
ros2 run tram_state_estimator tram_estimator --ros-args -p wheel_scale_online:=false
```

В логе при старте:
`вагон 30618: meas_scale 1.001362 (общий лист 1.001093), онлайн-масштаб колёс вкл.`

Проверено в настоящей ноде ROS 2 (`ros2 launch` с `vehicle:=30639`, `auto`,
`foo`; `ros2 run` с `-p vehicle:=30639` - целое число - и без листа): значение
доходит, у `foo` - предупреждение и `auto`.

Лист ОЦЕНКИ (`config/eval/tram.yaml`) устроен так же, но масштаб каждого вагона
подогнан только по его обучающим записям (30618 - 1,001408 по 41 записи,
30639 - 1,000367 по 14). Отложенные записи в калибровку листа оценки не входят.

`vehicle` меняет только `meas_scale`. Карта путей общая: её множитель пути
подогнан при общем `meas_scale` на всех обучающих записях, поэтому путь каждого
вагона идёт по его собственному масштабу колёс.

## 4. Что не стали разделять (выбор на train)

Проверка по 5 частям на обучающих записях каждого вагона: подгонка без части,
проверка на ней (`analysis/calib_vehicle_study.py`).

**Таблица привода A(ручка, скорость)** - СКО ускорения модели привода на
отложенной части:

| вагон | общая таблица | своя таблица |
|---|---:|---:|
| 30618 | 0,1631 м/с² | 0,1630 м/с² |
| 30639 | 0,1547 м/с² | 0,1496 м/с² |

**Скорость полной связки** (ядро как в ноде, лист ОЦЕНКИ, против скорости GNSS
master) на отложенных частях, таблица и масштаб «общие» или «своего вагона»:

| вагон | вариант | MAE, м/с | смещение, м/с |
|---|---|---:|---:|
| 30618 (41 запись) | общий лист | **0,0307** | −0,0047 |
| | свой масштаб | 0,0308 | **−0,0041** |
| | своя таблица | 0,0308 | −0,0049 |
| | свой масштаб и таблица | 0,0309 | −0,0042 |
| 30639 (14 записей) | общий лист | 0,0406 | +0,0073 |
| | свой масштаб | 0,0433 | **+0,0013** |
| | своя таблица | **0,0401** | +0,0075 |
| | свой масштаб и таблица | 0,0429 | +0,0016 |

Что решили:

- **Таблица привода остаётся общей.** Для 30618 своя таблица ничего не даёт.
  Для 30639 даёт −1 % MAE - на 14 записях это в пределах разброса, а жюри
  30639 не проверяет. Лишние 341 число в листе того не стоят.
- **Масштаб колёс - свой у каждого вагона.** Для 30618 разница с общим листом
  всего 0,03 % (лист жюри) и 0,01 % (лист оценки): MAE тот же с точностью
  0,0001 м/с, смещение ближе к нулю. Для 30639 смещение падает с +0,007 до
  +0,001 м/с, но MAE на train хуже (0,0433 против 0,0406). Причина - две даты
  30639 с масштабом, различающимся на 1,1 % (раздел 2): одно число на вагон
  попадает между ними, и записи от 26.08 с ним хуже, чем с общим листом.

Почему MAE и смещение расходятся: 28 % времени вагон стоит, GNSS на стоянке
показывает шум больше нуля, а оценка - ноль (смещение на стоянке −0,013 м/с).
На ходу смещение и так положительное (+0,005..+0,017 м/с по фазам,
[EVAL.md §3.1](EVAL.md#31-скорость)). Больший масштаб приближает к нулю общее
смещение, но на ходу увеличивает ошибку.

## 6. Главный риск - дата, а не вагон: онлайн-масштаб колёс

Дату записи нода не знает. Если жюри проиграет запись 30618 с «другой» даты,
как 03.09, масштаб колёс уйдёт на 1 %. На обучающих записях (лист и карта
ОЦЕНКИ, `vehicle: auto`, онлайн-масштаба колёс нет) это выглядит так:

| вагон, дата | записей | скорость MAE, м/с | смещение, м/с | 3D ср., м | вдоль RMSE, м |
|---|---:|---:|---:|---:|---:|
| 30618, 27.07 | 20 | 0,0238 | −0,0003 | 1,82 | 3,0 |
| 30618, 10.08 | 9 | 0,0453 | +0,0071 | 1,86 | 2,7 |
| 30618, 26.08 | 8 | 0,0216 | −0,0036 | 1,48 | 2,2 |
| **30618, 03.09** | 4 | **0,0523** | **−0,0447** | **5,78** | **29,6** |
| 30639, 26.08 | 8 | 0,0273 | −0,0170 | 2,81 | 4,6 |
| **30639, 05.05** | 6 | **0,0560** | **+0,0363** | **18,54** | **23,8** |

Скорость на «чужой» дате хуже вдвое, положение - втрое. Параметр `vehicle`
здесь не поможет: масштаб меняется у того же вагона.

**Что было.** Онлайн-подстройка масштаба пути по остановкам (`scale_adapt`)
правит только положение и медленно: на 03.09 к концу поездки она доходит до
1,001 при нужных 1,010, а в 3 записях из 4 выключает себя сама (отрезки между
остановками «противоречат» друг другу больше чем на 1,2 %).

**Что сделано: `wheel_scale_online`** (`vehicle.py`, класс `OnlineWheelScale`).
Та же привязка к остановкам даёт масштаб колёс: на каждом отрезке между
остановками - отношение пути по карте к пути колёс. Нода берёт отрезки не
короче 300 м, отбрасывает явные ошибки привязки (отношение дальше 3 % от 1),
и когда таких отрезков не меньше двух, считает масштаб как весь путь по карте
на весь путь колёс (длинный отрезок весит больше: ошибка привязки - метры).
Если он отходит от 1 больше чем на 0,5 %, скорость на выходе умножается на
него (не больше ±2 %). Всё причинно: учитываются только законченные отрезки.
Новый прогон (сброс связки) - оценка заново. Положение этот масштаб не
трогает.

`30618_defd0170`, ×5, лист жюри): MAE скорости против GNSS 0,0796 м/с с

Как выбирали: сначала по 30618 (его проверяют), потом по всем. «Мёртвая зона
0,3 %» и выбранный вариант вровень (−4,1 и −4,0 % у 30618, −5,2 и −5,0 % по
всем), но у выбранного на всех обычных датах 30618 ровно 0 %: поправка
включается только там, где масштаб действительно ушёл. Мёртвую зону 0,5 %
выбрали ещё в первом «что если» 26.09 (медиана отрезков, строка 3), до
перебора. Всего в переборе 48 вариантов (длина отрезка 200/300/500 м, порог
выброса 2/3/5 %, предел 1/2/3 %, мёртвая зона 0-1 %) -
`docs/data/vehicles/study_grid.json`. Честно: варианты «без первого отрезка» и
«по длине / медиана» добавили в перебор после того, как посмотрели на
отложенную запись `30618_21dd3af3` (раздел 5); выбор между ними всё равно
сделан по train, и число на отложенных от этого не улучшилось (+1,9 %).

**GNSS посреди маршрута и онлайн-масштаб** (27.09). Масштаб колёс
учится по привязкам к остановкам: путь по карте против пути колёс. Поправки
GNSS двигают курсор, и сдвиг привязки после них уже не ошибка колёс; без защиты
скорость начинала зависеть от GNSS (отложенные, GNSS весь прогон против 3 с:
`30618_21dd3af3` MAE 0,0326 → 0,0278, `30639_92226df0` 0,0358 → 0,0583 м/с).
Теперь с первой точкой-кандидатом коррекции связка снимает копию положения,
которая поправок GNSS не получает, и масштаб колёс учится по ней
(`Runner._shadow_position`). Итог: с GNSS после окна скорость на каждом шаге та
же, что при GNSS только в окне (тест
`test_online_wheel_scale_ignores_mid_route_gnss`); без GNSS после окна копии нет
и ничего не меняется.

**Чего не сделано.** Положение по-прежнему ведёт `scale_adapt` (медленная и
выключающаяся подстройка масштаба пути). Та же оценка могла бы вести и путь
(на 03.09 вдоль RMSE 29,6 м против ~3 м на обычных датах) - это следующий шаг
([MODEL.md](../MODEL.md) §10 п. 5).

## 7. Как пересчитать

```bash
# в образе, из корня репозитория (data и кэш - только чтение);
# PYTHONPATH=ros2_ws/src/tram_state_estimator:tools:analysis
python3 analysis/calib_vehicle.py --runs          # таблица раздела 2
python3 analysis/calib_vehicle.py --write         # блок vehicles в калибровках
python3 ros2_ws/src/tram_state_estimator/tools/gen_params.py   # листы
python3 analysis/calib_vehicle_study.py drive     # раздел 4, таблица привода
python3 analysis/calib_vehicle_study.py speed     # раздел 4, скорость
python3 analysis/calib_vehicle_study.py grid      # раздел 6, перебор онлайн-масштаба
# раздел 5: по прогону eval.py на вариант
python3 tools/eval.py --set vehicle=auto,wheel_scale_online=false --no-inject \
    --no-gnss-full --no-doc --baseline none --out out/vehicle/h_main
#   ... vehicle=30618,wheel_scale_online=false -> h_30618;
#   vehicle=30618,wheel_scale_online=true -> h_jury; vehicle=match,... -> h_match
python3 tools/vehicle_report.py main=out/vehicle/h_main vehicle=30618=out/vehicle/h_30618 \
    жюри=out/vehicle/h_jury свой=out/vehicle/h_match
# раздел 6, таблица по датам: tools/eval.py --runs <обучающие записи вагона>
#   --set vehicle=auto,wheel_scale_online=false … --out out/vehicle/train18_auto, затем
python3 tools/vehicle_report.py auto=out/vehicle/train18_auto --by-date
```

Время: `calib_vehicle.py` - около минуты, `study drive` - 2 мин, `study speed`
и `study grid` - по 15-25 мин на 4-6 ядрах, `eval.py` на 15 отложенных -
3-5 мин на 5 ядрах.

`--set vehicle=match` - только для оценки: вагон берётся из имени записи.
Итоги расчётов этого документа - `docs/data/vehicles/*.json`: разделы 4
(`study_drive`, `study_speed`), 5 (`report_holdout`), 6 (`report_train18`,
`report_train39`, `study_grid`; первый «что если» 26.09 - `study_online`).
