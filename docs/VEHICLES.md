# Учёт различий трамваев

Организаторы (26.09, 18:05): проверять будут **только вагон 30618**, а учёт
различий трамваев засчитают в плюс. Здесь — чем отличаются вагоны 30618 и 30639,
что из этого нода учитывает и сколько это даёт на отложенных записях.

## 1. Коротко

- Вагоны отличаются **масштабом колёс**: сколько км/ч показывают датчики тележек
  при той же скорости по GNSS. По всем данным 30639 «спешит» на 0,38 %
  относительно 30618.
- **У одного вагона масштаб меняется по датам сильнее, чем между вагонами:**
  30618 3 сентября — на 1,1 % против июля–августа, 30639 5 мая — на 1,1 % против
  26 августа. Причину данные не называют (возможно, износ или обточка колёс);
  дату записи нода не знает.
- Таблица привода (какое ускорение даёт ручка) у вагонов практически одна:
  отдельная таблица для 30618 ничего не даёт, для 30639 модель привода точнее
  на 3 %, но на скорость это почти не влияет (раздел 4).
- Нода получила параметр **`vehicle`**: `30618` (по умолчанию, для жюри),
  `30639` или `auto`. Известный вагон — берётся его масштаб колёс. `auto` — общий
  лист по обоим вагонам (как было до этой правки, совпадает бит в бит).
- Для 30618 параметр почти ничего не меняет (±0,0001 м/с): общий лист и так
  почти весь из его записей. Для 30639 свой масштаб даёт −4 % MAE скорости и
  −0,2 м средней ошибки положения (раздел 5).
- Главный риск для проверки — не вагон, а дата: на 03.09 у 30618 скорость хуже
  вдвое, положение — втрое. Как это лечить — раздел 6.

## 2. Что различается: масштаб колёс

Масштаб колёс `meas_scale` — поправка к показаниям тележек: скорость GNSS,
делённая на среднее двух тележек, на ровном ходу (скорость больше 3 м/с,
ускорение меньше 0,1 м/с², тележки согласны). Считается по всем записям с GNSS,
медиана по всем отсчётам (`analysis/calib_vehicle.py`).

| вагон | дата | записей с GNSS | `meas_scale` | к общему |
|---|---|---:|---:|---:|
| 30618 | 27.07 | 26 | 1,00076 | −0,03 % |
| 30618 | 10.08 | 10 | 1,00147 | +0,04 % |
| 30618 | 26.08 | 12 | 1,00123 | +0,01 % |
| 30618 | **03.09** | 4 | **1,01256** | **+1,15 %** |
| 30639 | **05.05** | 9 | **0,99244** | **−0,86 %** |
| 30639 | 26.08 | 8 | 1,00380 | +0,27 % |
| **30618** | все | 52 | **1,00136** | +0,03 % |
| **30639** | все | 17 | **0,99757** | −0,35 % |
| оба | все | 69 | 1,00109 | — |

Что видно:

- 30618 весь июль и август стабилен (разброс ±0,04 %), и общий лист почти
  совпадает с ним: в данных 52 записи 30618 против 17 у 30639.
- В один день (26.08) вагоны отличаются на 0,26 %. Это и есть «разница трамваев».
- Смена даты у одного вагона даёт 1,1–1,2 %. Ошибка масштаба 1 % — это 1 % пути:
  около 54 м на 5,4 км линии, если бы не было привязки к остановкам.

## 3. Параметр `vehicle`

В листе `config/tram.yaml` (его делает `tools/gen_params.py` из калибровки):

```yaml
vehicle: "30618"                          # 30618 | 30639 | auto
vehicle_ids: ["30618", "30639"]
vehicle_meas_scale: [1.001362, 0.997575]  # лист жюри: все записи вагона
```

| значение | что делает нода |
|---|---|
| `30618` (по умолчанию) | `meas_scale` = 1,001362 — по всем записям 30618 |
| `30639` | `meas_scale` = 0,997575 — по всем записям 30639 |
| `auto` | общий лист как есть: `meas_scale` 1,001093 по обоим вагонам |
| что-то другое | как `auto`, в логе предупреждение «вагон … неизвестен» |

Онлайн-подстройка масштаба пути по привязкам к остановкам (`scale_adapt`,
±1 %) работает при любом значении. Для `auto` это единственная подстройка под
вагон, и она слабая (раздел 6).

Как задать:

```bash
ros2 launch tram_state_estimator tram.launch.py vehicle:=30639
ros2 run tram_state_estimator tram_estimator --ros-args -p vehicle:=auto
```

В логе при старте: `вагон 30618: meas_scale 1.001362 (общий лист 1.001093)`.

Лист ОЦЕНКИ (`config/eval/tram.yaml`) устроен так же, но масштаб каждого вагона
подогнан только по его обучающим записям (30618 — 1,001408 по 41 записи,
30639 — 1,000367 по 14). Отложенные записи в калибровку листа оценки не входят.

Меняется только `meas_scale`. Карта путей общая: её множитель пути подогнан при
общем `meas_scale` на всех обучающих записях, поэтому путь каждого вагона
идёт по его собственному масштабу колёс.

## 4. Что не стали разделять (выбор на train)

Проверка по 5 частям на обучающих записях каждого вагона: подгонка без части,
проверка на ней (`analysis/calib_vehicle_study.py`).

**Таблица привода A(ручка, скорость)** — СКО ускорения модели привода на
отложенной части:

| вагон | общая таблица | своя таблица |
|---|---:|---:|
| 30618 | 0,1631 м/с² | 0,1630 м/с² |
| 30639 | 0,1547 м/с² | 0,1496 м/с² |

**Скорость полной связки** (ядро как в ноде, лист ОЦЕНКИ, против скорости GNSS
master) на отложенных частях, таблица и масштаб «общие» или «своего вагона»:

| вагон | вариант | MAE, м/с | смещение, м/с |
|---|---|---:|---:|
| 30618 (41 запись) | общий лист | **0,0307** | −0,0047 |
| | свой масштаб | 0,0308 | **−0,0041** |
| | своя таблица | 0,0308 | −0,0049 |
| | свой масштаб и таблица | 0,0309 | −0,0042 |
| 30639 (14 записей) | общий лист | 0,0406 | +0,0073 |
| | свой масштаб | 0,0433 | **+0,0013** |
| | своя таблица | **0,0401** | +0,0075 |
| | свой масштаб и таблица | 0,0429 | +0,0016 |

Что решили:

- **Таблица привода остаётся общей.** Для 30618 своя таблица ничего не даёт.
  Для 30639 даёт −1 % MAE — на 14 записях это в пределах разброса, а жюри
  30639 не проверяет. Лишние 341 число в листе того не стоят.
- **Масштаб колёс — свой у каждого вагона.** Для 30618 разница с общим листом
  всего 0,03 % (лист жюри) и 0,01 % (лист оценки): MAE тот же с точностью
  0,0001 м/с, смещение ближе к нулю. Для 30639 смещение падает с +0,007 до
  +0,001 м/с, но MAE на train хуже (0,0433 против 0,0406). Причина — две даты
  30639 с масштабом, различающимся на 1,1 % (раздел 2): одно число на вагон
  попадает между ними, и записи от 26.08 с ним хуже, чем с общим листом.

Почему MAE и смещение расходятся: 28 % времени вагон стоит, GNSS на стоянке
показывает шум больше нуля, а оценка — ноль (смещение на стоянке −0,013 м/с).
На ходу смещение и так положительное (+0,005…+0,017 м/с по фазам,
[EVAL.md §3.1](EVAL.md#31-скорость)). Больший масштаб приближает к нулю общее
смещение, но на ходу увеличивает ошибку.

## 6. Главный риск — дата, а не вагон

Дату записи нода не знает. Если жюри проиграет запись 30618 с «другой» даты,
как 03.09, масштаб колёс уйдёт на 1 %. На обучающих записях (лист и карта
ОЦЕНКИ, `vehicle: auto`) это выглядит так:

| вагон, дата | записей | скорость MAE, м/с | смещение, м/с | 3D ср., м | вдоль RMSE, м |
|---|---:|---:|---:|---:|---:|
| 30618, 27.07 | 20 | 0,0238 | −0,0003 | 1,82 | 3,0 |
| 30618, 10.08 | 9 | 0,0453 | +0,0071 | 1,86 | 2,7 |
| 30618, 26.08 | 8 | 0,0216 | −0,0036 | 1,48 | 2,2 |
| **30618, 03.09** | 4 | **0,0523** | **−0,0447** | **5,78** | **29,6** |
| 30639, 26.08 | 8 | 0,0273 | −0,0170 | 2,81 | 4,6 |
| **30639, 05.05** | 6 | **0,0560** | **+0,0363** | **18,54** | **23,8** |

Скорость на «чужой» дате хуже вдвое, положение — втрое. Параметр `vehicle` здесь
не поможет: масштаб меняется у того же вагона.

**Что уже есть.** Онлайн-подстройка масштаба пути по остановкам (`scale_adapt`)
правит только положение и медленно: на 03.09 к концу поездки она доходит до
1,001 при нужных 1,010, а в 3 записях из 4 выключает себя сама (отрезки между
остановками «противоречат» друг другу больше чем на 1,2 %). Всего на train она
выключилась в 26 записях из 61.

**Что можно сделать (проверено «что если», в ноде нет).** Та же привязка к
остановкам даёт масштаб колёс точно: на каждом отрезке между остановками
длиннее 300 м — отношение пути по карте к пути колёс, медиана по отрезкам
(не меньше двух), поправка не больше ±2 %. На 03.09 оценка к концу поездки —
1,0103 при истинных 1,0100, на 05.05 у 30639 — 0,994 при 0,990. Если умножать
на неё и скорость (только когда поправка больше 0,5 %), на train:

| вагон, дата | записей | MAE как сейчас | MAE с поправкой | смещение как сейчас | с поправкой |
|---|---:|---:|---:|---:|---:|
| 30618, 27.07 | 22 | 0,0238 | 0,0238 | −0,0003 | −0,0005 |
| 30618, 10.08 | 11 | 0,0451 | 0,0458 | +0,0069 | +0,0067 |
| 30618, 26.08 | 9 | 0,0216 | 0,0219 | −0,0037 | −0,0033 |
| **30618, 03.09** | 4 | **0,0523** | **0,0402** | −0,0447 | −0,0221 |
| 30639, 26.08 | 9 | 0,0271 | 0,0281 | −0,0169 | −0,0118 |
| **30639, 05.05** | 6 | **0,0560** | **0,0477** | +0,0363 | +0,0225 |
| все | 61 | 0,0328 | **0,0312** | −0,0018 | −0,0007 |

(Здесь все обучающие записи с GNSS, в таблице выше — только с полным GNSS,
поэтому число записей чуть разное.)

То есть на «обычных» датах плата — до +1,5 % MAE, на «чужой» — выигрыш 15–23 %.
Без мёртвой зоны 0,5 % обычные даты теряют до 9 %. Это правка связки
(`runner.py`: масштаб ядра по привязкам к остановкам), в этом потоке она не
сделана: `runner.py` сейчас правит поток GNSS, а GNSS посреди маршрута, если он
будет, даёт масштаб колёс ещё точнее. Расчёт — `analysis/calib_vehicle_study.py
online` (скорость умножается на оценку уже после связки, причинно: на каждом
шаге — только по отрезкам, законченным до него).

## 7. Как пересчитать

```bash
# в образе, из корня репозитория (data и кэш — только чтение)
python3 analysis/calib_vehicle.py --runs          # таблица раздела 2
python3 analysis/calib_vehicle.py --write         # блок vehicles в калибровках
python3 ros2_ws/src/tram_state_estimator/tools/gen_params.py   # листы
python3 analysis/calib_vehicle_study.py drive     # раздел 4, таблица привода
python3 analysis/calib_vehicle_study.py speed     # раздел 4, скорость
python3 analysis/calib_vehicle_study.py online    # раздел 6, «что если»
for v in auto 30618 match; do             # раздел 5
  python3 tools/eval.py --set vehicle=$v --no-inject --no-gnss-full --no-doc \
      --baseline none --out out/vehicle/hold_$v
done
python3 tools/vehicle_report.py main=out/vehicle/hold_auto \
    vehicle=30618=out/vehicle/hold_30618 vehicle=match=out/vehicle/hold_match
# раздел 6, таблица по датам: tools/eval.py --runs <обучающие записи вагона>
#   --set vehicle=auto … --out out/vehicle/train18_auto, затем
python3 tools/vehicle_report.py auto=out/vehicle/train18_auto --by-date
```

Время: `calib_vehicle.py` — около минуты, `study drive` — 2 мин, `study speed`
и `study online` — по 15–25 мин на 4–5 ядрах, `eval.py` на 15 отложенных —
3 мин на 4 ядрах.

`--set vehicle=match` — только для оценки: вагон берётся из имени записи.
Итоги расчётов этого документа (26.09) — `docs/data/vehicles/*.json`: разделы 4
(`study_drive`, `study_speed`), 5 (`report_holdout`), 6 (`report_train18`,
`report_train39`, `study_online`).
