## 1. Коротко

- **Масштаб колёс.** Это отношение скорости GNSS к показаниям тележек. 30639 «спешит» на
  0,38 % относительно 30618, но у одного вагона по датам масштаб меняется сильнее: на 1,1 %
  (30618 3 сентября, 30639 5 мая). Таблица привода у вагонов практически одна.
- **Параметр `vehicle`.** `30618` (по умолчанию), `30639` или `auto` - общий лист по обоим
  вагонам. Известный вагон получает свой масштаб колёс.
- **Параметр `wheel_scale_online`** (по умолчанию включён). Уточняет масштаб колёс на ходу по
  привязкам к остановкам: так нода справляется со сменой масштаба по датам, которую заранее не
  знает.
- **Результат.** На обучающих записях 30618 (46 записей, настройки выбраны только по ним) MAE
  скорости −4 %, на «чужой» дате 03.09 - −22 %, на остальных датах без изменений. На отложенных
  у 30639 MAE −20 % (0,0762 → 0,0610 м/с), у 30618 +1,9 % (0,0261 → 0,0266 м/с) из-за одной
  записи из 12. Положение у 30618 меняется на ±0,01 м.

## 2. Масштаб колёс по вагонам и датам

Масштаб колёс `meas_scale` - скорость GNSS, делённая на среднее двух тележек, на ровном ходу
(скорость больше 3 м/с, ускорение меньше 0,1 м/с², тележки согласны). Это медиана по всем
отсчётам записей с GNSS (`analysis/calib_vehicle.py`).

| Вагон | Дата | Записей с GNSS | `meas_scale` | К общему |
|:---|:---|---:|---:|---:|
| 30618 | 27.07 | 26 | 1,00076 | −0,03 % |
| 30618 | 10.08 | 10 | 1,00147 | +0,04 % |
| 30618 | 26.08 | 12 | 1,00123 | +0,01 % |
| 30618 | **03.09** | 4 | **1,01256** | **+1,15 %** |
| 30639 | **05.05** | 9 | **0,99244** | **−0,86 %** |
| 30639 | 26.08 | 8 | 1,00380 | +0,27 % |
| **30618** | все | 52 | **1,00136** | +0,03 % |
| **30639** | все | 17 | **0,99757** | −0,35 % |
| оба | все | 69 | 1,00109 | - |

30618 в июле и августе стабилен (±0,04 %), и общий лист почти совпадает с ним: 52 записи против
17 у 30639. В один день (26.08) вагоны отличаются на 0,26 %, а смена даты у одного вагона даёт
1,1-1,2 %. Причину данные не называют (возможно, износ или обточка колёс). Ошибка масштаба 1 % -
это 1 % пути: около 54 м на 5,4 км линии без привязки к остановкам.

## 3. Параметры `vehicle` и `wheel_scale_online`

Ключи вагона в листе жюри `config/tram.yaml`, с которым нода работает по умолчанию (лист строит
`ros2_ws/src/tram_state_estimator/tools/gen_params.py` из калибровки):

```yaml
vehicle: "30618"
vehicle_ids: ["30618", "30639"]
vehicle_meas_scale: [1.001362, 0.997575]
wheel_scale_online: true
```

| Значение `vehicle` | Что делает нода |
|:---|:---|
| `30618` (по умолчанию) | `meas_scale` = 1,001362 - по всем записям 30618 |
| `30639` | `meas_scale` = 0,997575 - по всем записям 30639 |
| `auto` | общий лист как есть: `meas_scale` 1,001093 по обоим вагонам |
| другое | как `auto`, в логе предупреждение «вагон … неизвестен» |

- **Онлайн-подстройки работают при любом `vehicle`.** Масштаб пути для положения
  (`scale_adapt`) и масштаб колёс для скорости (`wheel_scale_online`) - обе по привязкам к
  остановкам.
- **Карта путей общая.** `vehicle` меняет только `meas_scale`. Множитель пути карты подогнан при
  общем `meas_scale`, поэтому путь каждого вагона идёт по его собственному масштабу колёс.
- **Лист оценки** `config/eval/tram.yaml` устроен так же, но масштаб вагона подогнан только по
  обучающим записям: 30618 - 1,001408 по 41 записи, 30639 - 1,000367 по 14.

Команды ниже выполняются в оболочке ROS 2 с собранным пакетом.

Запустить ноду для вагона 30639.

```bash
ros2 launch tram_state_estimator tram.launch.py vehicle:=30639
```

Запустить ноду без онлайн-масштаба колёс.

```bash
ros2 run tram_state_estimator tram_estimator --ros-args -p wheel_scale_online:=false
```

Строка лога при старте с листом по умолчанию:

```text
вагон 30618: meas_scale 1.001362 (общий лист 1.001093), онлайн-масштаб колёс вкл.
```

Проверено в ноде ROS 2: `ros2 launch` с `vehicle:=30639`, `auto` и `foo`, `ros2 run` с
`-p vehicle:=30639` (целое число) и без листа. Значение доходит, у `foo` - предупреждение и
`auto`.

## 6. Онлайн-масштаб колёс: смена масштаба по датам

Дату записи нода не знает, а на «чужой» дате, как 03.09, масштаб колёс уходит на 1 %. Так это
выглядит на обучающих записях без онлайн-масштаба колёс (лист и карта оценки, `vehicle: auto`):

| Вагон, дата | Записей | Скорость MAE, м/с | Смещение, м/с | 3D ср., м | Вдоль RMSE, м |
|:---|---:|---:|---:|---:|---:|
| 30618, 27.07 | 20 | 0,0238 | −0,0003 | 1,82 | 3,0 |
| 30618, 10.08 | 9 | 0,0453 | +0,0071 | 1,86 | 2,7 |
| 30618, 26.08 | 8 | 0,0216 | −0,0036 | 1,48 | 2,2 |
| **30618, 03.09** | 4 | **0,0523** | **−0,0447** | **5,78** | **29,6** |
| 30639, 26.08 | 8 | 0,0273 | −0,0170 | 2,81 | 4,6 |
| **30639, 05.05** | 6 | **0,0560** | **+0,0363** | **18,54** | **23,8** |

Скорость на «чужой» дате хуже вдвое, положение - втрое, и `vehicle` здесь не поможет: масштаб
меняется у того же вагона. Подстройка масштаба пути `scale_adapt` правит только положение и
медленно: на 03.09 она доходит до 1,001 при нужных 1,010, а в 3 записях из 4 выключается сама
(отрезки между остановками расходятся больше чем на 1,2 %).

**Как работает `wheel_scale_online`** (класс `OnlineWheelScale` в `vehicle.py`):

- **Оценка.** На законченных отрезках между остановками не короче 300 м считается отношение пути
  по карте к пути колёс. Отношение дальше 3 % от 1 отбрасывается как ошибка привязки. Когда
  отрезков не меньше двух, масштаб - весь путь по карте на весь путь колёс: длинный отрезок
  весит больше.
- **Поправка.** Если масштаб отходит от 1 больше чем на 0,5 %, скорость на выходе умножается на
  него, но не больше чем на ±2 %. Положение он не трогает, после сброса связки оценка
  начинается заново.
- **GNSS посреди маршрута.** Поправки GNSS двигают курсор карты, поэтому масштаб учится по копии
  положения без этих поправок (`Runner._shadow_position`). Без копии скорость зависела бы от
  GNSS (отложенные, GNSS весь прогон против 3 с): `30618_21dd3af3` MAE 0,0326 → 0,0278,
  `30639_92226df0` 0,0358 → 0,0583 м/с. С копией скорость та же, что при GNSS только в окне
  (тест `test_online_wheel_scale_ignores_mid_route_gnss`).

В ноде ROS 2 (`tools/ros_e2e.sh`, запись `30618_defd0170` от 03.09, ×5, лист жюри) MAE скорости
против GNSS - 0,0796 м/с без онлайн-масштаба и 0,0424 м/с с ним (смещение −0,079 → −0,019 м/с).
Выходов 20 992 из 20 992, 20 Гц по меткам, задержка вход → выход p99 13 мс, как и без него.

**Выбор настроек - только на train** (`analysis/calib_vehicle_study.py grid`: 61 обучающая
запись с GNSS, лист и карта оценки, у каждой записи масштаб своего вагона, поправка тем же
классом, что в ноде). Выбран вариант: не меньше 2 отрезков, мёртвая зона 0,5 %, масштаб по
длине. Остальные строки отличаются от него одной настройкой. MAE скорости, м/с, в скобках -

## 7. Как пересчитать

Команды выполняются из корня репозитория в оболочке образа, как в
[README: воспроизведение по шагам](../README.md#воспроизведение-по-шагам): `PYTHONPATH` с
`ros2_ws/src/tram_state_estimator`, `tools` и `analysis`, записи и кэш - только на чтение.

Вывести масштаб колёс по записям (раздел 2).

```bash
python3 analysis/calib_vehicle.py --runs
```

Записать блок `vehicles` в калибровки.

```bash
python3 analysis/calib_vehicle.py --write
```

Пересобрать листы параметров.

```bash
python3 ros2_ws/src/tram_state_estimator/tools/gen_params.py
```

Сравнить общую и свою таблицу привода (раздел 4).

```bash
python3 analysis/calib_vehicle_study.py drive
```

Сравнить скорость связки с общим и своим листом (раздел 4).

```bash
python3 analysis/calib_vehicle_study.py speed
```

Перебрать настройки онлайн-масштаба колёс (раздел 6).

```bash
python3 analysis/calib_vehicle_study.py grid
```

Посчитать один вариант на 15 отложенных записях (раздел 5).

```bash
python3 tools/eval.py --set <вариант> --no-inject --no-gnss-full --no-doc --baseline none \
    --out out/vehicle/<папка>
```

| Опция | Что делает |
|:---|:---|
| `--set` | переопределяет поля листа оценки |
| `--no-inject` | без инъекций аномалий |
| `--no-gnss-full` | без проверки «GNSS весь прогон» |
| `--no-doc` | не пишет `docs/EVAL.md` и графики |
| `--baseline none` | без раздела сравнения с другой версией |
| `--out` | папка итогов прогона |

| `<вариант>` | `<папка>` |
|:---|:---|
| `vehicle=auto,wheel_scale_online=false` | `h_main` |
| `vehicle=30618,wheel_scale_online=false` | `h_30618` |
| `vehicle=30618,wheel_scale_online=true` | `h_jury` |
| `vehicle=match,wheel_scale_online=true` | `h_match` |

`vehicle=match` - только для оценки: вагон берётся из имени записи.

Собрать таблицу раздела 5 из прогонов.

```bash
python3 tools/vehicle_report.py main=out/vehicle/h_main vehicle=30618=out/vehicle/h_30618 \
    жюри=out/vehicle/h_jury свой=out/vehicle/h_match
```

Посчитать обучающие записи вагона без онлайн-масштаба (таблица по датам раздела 6).

```bash
python3 tools/eval.py --runs <обучающие записи вагона> --set vehicle=auto,wheel_scale_online=false \
    --no-inject --no-gnss-full --no-doc --baseline none --out out/vehicle/train18_auto
```

`--runs` принимает записи через запятую.

Собрать таблицу по датам.

```bash
python3 tools/vehicle_report.py auto=out/vehicle/train18_auto --by-date
```

- **Время.** `calib_vehicle.py` - около минуты, `study drive` - 2 мин, `study speed` и
  `study grid` - по 15-25 мин на 4-6 ядрах, `eval.py` на 15 отложенных - 3-5 мин на 5 ядрах.

## 8. Ограничения

- **Мало записей 30639.** На train 14, и разница в 1 % MAE на них в пределах разброса; отложенных
  3, все от 05.05.
- **Короткие первые отрезки** могут дать неверный масштаб, как в записи `30618_21dd3af3`
  (раздел 5).
- **Положение на «чужой» дате.** Путь ведёт медленная и выключающаяся подстройка `scale_adapt`:
  на 03.09 вдоль RMSE 29,6 м против около 3 м на обычных датах. Та же оценка масштаба колёс
  могла бы вести и путь - это следующий шаг ([MODEL.md](../MODEL.md) §10 п. 5).
