# Соответствие ТЗ: требование → решение → код → проверка → результат

Каждая строка — пункт из [TZ_REQUIREMENTS.md](TZ_REQUIREMENTS.md) (PDF организаторов)
и из контракта судьи в [DATASET_README.md](DATASET_README.md) §5. Числа — из
[EVAL.md](EVAL.md) (15 чистых отложенных записей, лист и карта только по обучающим)
и из замеров реального времени (`tools/ros_probe.py`; сводки в git —
`docs/data/realtime/*/summary.json`, таблица — EVAL.md §7 и [JURY.md](JURY.md) §6).
Числа запуска «как у жюри» — из проверки с чистого клона (раздел 10). Пути к коду —
от корня репозитория; `pkg/` — это `ros2_ws/src/tram_state_estimator/`.

Как запускать проверки:

- **чистый ROS 2 Humble** — `source install/setup.bash`, нода
  `ros2 launch tram_state_estimator tram.launch.py`, затем `ros2 bag play <прогон> -d 3`
  ([JURY.md](JURY.md) §2–3);
- **Docker** — из корня репозитория: `docker compose up --build` (демо),
  `docker compose run --rm test` (сборка без сети и тесты),
  `docker compose run --rm eval` (оценка, нужны данные в `DATA_DIR`).

## 5. Признаки проскальзывания из ТЗ

| Признак (PDF) | Как распознаётся | Где в коде |
|---|---|---|
| Резкий рост скорости колёс без соответствующего ускорения по модели | предел ускорения колеса и скачок показания против собственного тренда (`slip_jump`, `a_slip_margin`); отвержение по невязке | `estimator_core.py` (`step`, `_correct`) |
| Несоответствие передней и задней тележек | согласие тележек (`agree_tol`): показание, согласное с другой тележкой, принимается, одиночное расхождение — нет | `estimator_core.py` (`_correct`) |
| Высокий тяговый момент при низкой производной скорости | насыщение сцепления: сила привода ограничена оценкой μ, при признаках срыва μ снижается к `mu_min` | `estimator_core.py` (адаптация `mu`, `tau_sat`, `tau_rec`) |
| Отрицательное рассогласование при торможении | юз: колёса ниже модели при торможении не принимаются; нули всех колёс на ходу — неоднозначность «стоим или скользим» | `estimator_core.py` (`_slip_all_update`, `ambiguous`) |
| Аномально высокая дисперсия измерений | оценка шума показаний по вторым разностям (`meas_noise`); выше паспортной — дисперсия измерения увеличивается (шум не принимается за срыв) | `estimator_core.py` (`_noise`) |

Подробно — [MODEL.md](../MODEL.md) §3 и §7, раздел «Соответствие постановке».

## 9. Консоль ноды

Нода пишет в терминал `ros2 launch` (копия — `~/.ros/log/`):

- при запуске — блок настроек: версия пакета и отпечаток кода (`код sha` — так же
  считается «Код пакета: sha» в шапке EVAL.md), лист параметров, вагон и масштаб колёс,
  карта путей (число точек, остановок, конечных, веток), система выхода (MGRS 37UCB,
  точка `base_link`, `frame_id`), правило GNSS, шаг сетки и частота, входные топики;
  первая строка блока — `оценщик запущен`;
- во время работы — «входы пошли», «положение есть» после выставки по GNSS и строка
  состояния раз в 10 с времени bag: частота, позиция ручки и режим ядра, скорость,
  x/y/z и σ, сколько тележек принято, флаги (срыв, «стоим или скользим»,
  недостоверно, прогноз пульса);
  предупреждения — только об отклонениях (сброс связки, разрыв меток, нет выставки
  по GNSS), с ограничением частоты;
- при останове (Ctrl+C) — итог: выходы, входы по видам, отброшенные метки и
  значения, сбросы, ошибки в колбэках, время шага связки; выход без трассировки.
