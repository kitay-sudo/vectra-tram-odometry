# Инструкция для жюри

Как собрать пакет, запустить его на своих записях и проверить выход. Числа точности взяты из
[EVAL.md](EVAL.md): 15 отложенных записей, лист параметров и карта путей только по обучающим
записям. Проверки сборки, ROS 2 и реального времени собраны в разделе 9.

Нода по скоростям двух тележек и позиции ручки контроллера публикует скорость и положение
трамвая в реальном времени. GNSS нужен только в первые 3 с bag для выставки положения; если он
есть и дальше, нода поправляет по нему положение (раздел 3а). На скорость GNSS не влияет.

## 1. Коротко

Команды выполняются в терминале с ROS 2 Humble из любой папки, `<репозиторий>` - папка клона.
Интернет не нужен.

Подключить ROS 2 Humble.

```bash
source /opt/ros/humble/setup.bash
```

Скопировать пакеты в новый workspace.

```bash
mkdir -p ~/vectra_ws/src && cp -r <репозиторий>/ros2_ws/src/* ~/vectra_ws/src/
```

Собрать пакеты.

```bash
cd ~/vectra_ws && colcon build
```

Подключить собранные пакеты (в каждом новом терминале).

```bash
source ~/vectra_ws/install/setup.bash
```

Запустить ноду в терминале 1.

```bash
ros2 launch tram_state_estimator tram.launch.py
```

Проиграть bag в терминале 2, когда нода напишет «жду входы».

```bash
ros2 bag play <путь к прогону> -d 3
```

Выход: `/result/velocity` и `/result/position`, 20 Гц, метки времени из bag. Положение - точка
`base_link` в плоских MGRS от угла квадрата 37UCB, `z` - высота уровня рельса (раздел 4).

## 1а. Проверка скриптом организаторов (check-code)

Нода организаторов `hackathon_solution_checker` сравнивает `/result/velocity` и
`/result/position` с эталоном `/localization/kinematic_state` из записи: пары по меткам времени с
допуском 0,05 с, RMSE и максимум ошибки. Наш скрипт запускает её вместе с нашим пакетом в чистом
`ros:humble-ros-base` (2 ядра, 512 МБ), запись идёт в реальном времени, около 23 мин. Команда
выполняется из корня репозитория в Git Bash или Linux, нужен Docker.

Повторить проверку организаторов.

```bash
tools/judge_check.sh --check <папка check-code>
```

| Опция | Что делает |
|:---|:---|
| `--check` | распакованный архив организаторов (`Dockerfile`, `src/`, `bags/`) |
| `--msgs theirs` | собрать их пакет сообщений (только `VelocitySensor`): проверка без типа ручки |

Результат на их записи `30618_88aea4d9` (22 мин, числа из вывода их ноды, 0 сбросов связки):

| Метрика | Значение |
|:---|---:|
| скорость, RMSE / максимум | 0,042 / 0,319 м/с |
| положение 3D, RMSE / максимум | 1,43 / 11,26 м |
| x, y, z, RMSE | 1,28 / 0,64 / 0,10 м |
| пар скорости и положения | 26 233 |

- **Сдвиг скорости.** Эталон скорости в их записи сглажен и запаздывает относительно тележек
  около 0,1 с, поэтому нода сдвигает скорость на `speed_output_delay_s` = 0,08 с. Без сдвига
  RMSE скорости 0,059 м/с. Положение не сдвигается.
- **Пакет сообщений.** Их `tram_vehicle_msgs` содержит только `VelocitySensor`, наш - тот же
  файл байт в байт и `DriverControllerCommand` (ручка). Скопируйте наши пакеты в их `src/`: папка
  совпадёт по имени, останется наш пакет. При «Duplicate package names» отключите их копию.
- **Без типа ручки нода не падает.** Она пишет «Внимание: в tram_vehicle_msgs нет
  DriverControllerCommand, ручка не используется» и работает по тележкам.

Отключить их копию пакета сообщений (из папки их workspace).

```bash
touch src/tram_vehicle_msgs/COLCON_IGNORE
```

## 2. Сборка без Docker

Нужен только ROS 2 Humble (`ros-humble-ros-base`): пакет берёт из него `rclpy`, стандартные
сообщения, `launch`, `launch_ros`, `python3-numpy`, `python3-yaml`. `rosdep` и интернет не
нужны. В чистом `ros:humble-ros-base` с `docker run --network none` 3 пакета собираются за
5-12 с. Команды - в разделе 1.

| Пакет | Что это |
|:---|:---|
| `tram_vehicle_msgs` | сообщения кейса `VelocitySensor`, `DriverControllerCommand`: те же `.msg`, что в датасете |
| `tram_msgs` | наше сообщение диагностики `EstimatorStatus` |
| `tram_state_estimator` | нода `tram_estimator` (Python), лист `config/tram.yaml`, карта `config/track_map.npz`, launch |

Если в workspace уже есть `tram_vehicle_msgs` из датасета, оставьте наш: colcon не соберёт два
пакета с одним именем. Поля сообщений те же, но в наш манифест добавлен `<maintainer>`: без него
`colcon build` в Humble падает.

## 3. Запуск

Команды запуска - в разделе 1. Сначала нода, потом bag: окно выставки по GNSS - первые 3 с bag,
и если нода его пропустит, положения в этом прогоне не будет.

Пример вывода `ros2 launch` (префиксы логгера убраны):

```text
оценщик запущен: tram_state_estimator 0.1.0, код sha <16 знаков>
  лист: .../share/tram_state_estimator/config/tram.yaml [/tram_state_estimator] (...)
  вагон 30618: meas_scale 1.001362 (общий лист 1.001093), онлайн-масштаб колёс вкл.
  карта есть: .../share/tram_state_estimator/config/track_map.npz (точек осей 17554, остановок 51, конечных 4, веток у конечных 3)
  выход mgrs от квадрата 37UCB непрерывно; точка base_link (карта по base_link); frame_id map, child_frame_id base_link
  GNSS: выставка по первым 3.0 с; коррекция по GNSS после окна вкл (только положение вдоль пути, скорость от GNSS не зависит)
  шаг 50 мс (20 Гц) по header.stamp входов; единицы km_h; пульс 0.2 с; QoS входов best-effort
  жду входы: /vehicle/front_bogie_velocity, /vehicle/rear_bogie_velocity, /vehicle/driver_position_cmd, /sensing/gnss/master/fix, /sensing/gnss/rover/fix
```

- **Ход работы.** После «жду входы» нода готова. С началом bag она пишет «входы пошли», затем
  «положение есть с метки …» и раз в 10 с строку состояния: частота, ручка и режим, скорость,
  x, y, z и их σ, сколько тележек принято.
- **Код sha.** Если он совпадает с «Код пакета: sha» в шапке [EVAL.md](EVAL.md), числа отчёта
  посчитаны на этом коде; если нет, код менялся после расчёта (пересчёт - раздел 7).
- **`ros2 run`.** `ros2 run tram_state_estimator tram_estimator` без `--params-file` берёт лист
  пакета (в логе «без --params-file: лист пакета»), выход тот же. Launch вдобавок перезапускает
  ноду при падении (`respawn`).
- **Проигрывание.** По ответу организаторов режим не важен: нода работает по `header.stamp`
  входов, `--clock` и `use_sim_time` не нужны, темп `-r` любой. `-d 3` даёт DDS время найти
  подписчиков: под нагрузкой обнаружение занимало до 3,7-5,8 с после старта плеера, поэтому ноду
  запускайте заранее, а bag - с задержкой не меньше 3 с.
- **Несколько bag подряд.** Лучше перезапускать ноду. Без перезапуска разрыв меток (назад больше
  10 с, вперёд больше 60 с) нода считает новым прогоном и выставляется заново. Проверено: второй
  bag раньше первого на 142 с - 1 сброс, ошибка в конце 0,24 м.
- **Останов.** Ctrl+C в терминале ноды, выход без трассировки.
- **Вагон.** По умолчанию 30618, на нём идёт проверка организаторов; для неизвестного вагона -
  `vehicle:=auto` (общий лист по обоим). Масштаб колёс записи нода уточняет сама по остановкам
  (`wheel_scale_online`). Разница вагонов - [VEHICLES.md](VEHICLES.md).

Запустить ноду для записи вагона 30639.

```bash
ros2 launch tram_state_estimator tram.launch.py vehicle:=30639
```

## 3а. GNSS посреди маршрута

По ответу организаторов GNSS гарантирован в первые секунды записи. Посреди маршрута топик пуст
или почти пуст, но его можно использовать для коррекции. Нода делает это сама:

- **Поправка.** Каждая точка GNSS после окна выставки - кандидат поправки положения вдоль пути,
  поперёк держит карта. Вес по `NavSatFix.status`: RTK (2) - σ 0,5 м, без поправок (0) - σ 5 м.
- **Выбросы.** Отбрасываются скачки, метки дальше 0,3 с от последнего входа тележек и пары
  антенн со сбитой базой. Поправка больше 3 м - только по RTK после 3 согласных эпох подряд, без
  RTK - только малые, не чаще раза в 20 с.
- **Скорость.** GNSS её не трогает: сетка, скорость, σ и диагностика те же, что при GNSS только
  в первые 3 с ([EVAL.md](EVAL.md) раздел 5).
- **Запись с середины.** Если GNSS в начале не было, выставку откроет первая годная точка.

Запустить ноду без коррекции, с GNSS только для выставки.

```bash
ros2 run tram_state_estimator tram_estimator --ros-args -p gnss_correction:=false
```

Результат на записях вагона 30618 - [EVAL.md](EVAL.md) раздел 5.1, устройство -
[POSITION_FRAME.md](POSITION_FRAME.md) §12.

## 4. Система координат положения

По ответам организаторов: плоские **MGRS**, оси по REP-103 (x - восток, y - север, z - вверх),
от угла квадрата **37U CB непрерывно**, как их карта pathgraph: x = UTM E − 300 000,
y = UTM N − 6 100 000. На границе квадратов (E = 400 км) x плавно переходит через 100 000. Точка
вагона - **`base_link`**: ось поворота передней тележки на уровне касания колеса и рельса.

| Ось | Значение на выходе |
|:---|:---|
| `x` | MGRS easting от угла 37U CB, м (на линии около 98 800…103 700) |
| `y` | MGRS northing от угла 37U CB, м |
| `z` | высота уровня рельса, м, в той же системе, что `z` pathgraph |

- **Высота.** Проверка организаторов считает ошибку по x, y и z. `z` берётся из карты: в части
  pathgraph - его `z`, за его концами - высота антенн по GNSS датасета минус 3,0 м. Без карты -
  `altitude` из `NavSatFix` минус 3,0 м.
- **Кадры.** `frame_id` = `map`, `child_frame_id` = `base_link`. Положение публикуется с первой
  годной точки GNSS master, скорость - с первого шага.
- **Антенны.** По tf организаторов master (−9,873; 0; 3,0), rover (2,563; 0; 3,0) в `base_link`.
  При выставке `base_link = master + 9,873/12,436 · (rover − master)`, `z` минус 3,0 м, дальше
  точка ведётся по карте путей ([POSITION_FRAME.md](POSITION_FRAME.md)).

Параметры системы выхода задаются в `config/tram.yaml`, остальные параметры - в README, раздел
«[Настройки](../README.md#настройки)»:

| Параметр | По умолчанию | Что задаёт |
|:---|:---|:---|
| `projection` | `mgrs` | система: `mgrs`, `utm` (UTM E/N зоны 37), `enu` (плоскость в первой точке master), `equirect` |
| `mgrs_grid` | `"37UCB"` | квадрат, непрерывно от его угла; `""` - свой квадрат у каждой точки (скачок 100 км на границе) |
| `mgrs_guard_m` | `0.0` | при `mgrs_grid: ""`: ближе этого к краю квадрата положение не публикуется; `0` - выключено |
| `output_point` | `base_link` | точка выхода; `master` - антенна master (на 9,87 м позади и на 3 м выше) |
| `antenna_master_x`, `antenna_rover_x`, `antenna_z` | `-9.873`, `2.563`, `3.0` | положение антенн в `base_link`, м |
| `origin_lat`, `origin_lon`, `origin_alt` | NaN | начало для `projection: enu`; NaN - первая точка master |

Любой параметр можно задать аргументом запуска, остальные нода возьмёт из листа пакета.

Запустить ноду с другим квадратом отсчёта.

```bash
ros2 run tram_state_estimator tram_estimator --ros-args -p mgrs_grid:=37UDB
```

Запустить ноду с выходом в точке антенны master.

```bash
ros2 run tram_state_estimator tram_estimator --ros-args -p output_point:=master
```

Запустить ноду со своим листом параметров.

```bash
ros2 launch tram_state_estimator tram.launch.py params_file:=<путь к листу.yaml>
```

Лист пакета после сборки -
`~/vectra_ws/install/tram_state_estimator/share/tram_state_estimator/config/tram.yaml`: правка
строки под `ros__parameters` действует после перезапуска launch.

## 5. Топики

Входы (подписка best-effort, глубина 50):

| Топик | Тип | Как используется |
|:---|:---|:---|
| `/vehicle/front_bogie_velocity` | `tram_vehicle_msgs/msg/VelocitySensor` | скорость передней тележки, км/ч |
| `/vehicle/rear_bogie_velocity` | `tram_vehicle_msgs/msg/VelocitySensor` | скорость задней тележки, км/ч |
| `/vehicle/driver_position_cmd` | `tram_vehicle_msgs/msg/DriverControllerCommand` | позиция ручки −15..+15 |
| `/sensing/gnss/master/fix`, `/sensing/gnss/rover/fix` | `sensor_msgs/msg/NavSatFix` | положение и курс в первые 3 с, дальше поправка вдоль пути (раздел 3а) |

Скорость тележек в км/ч по ответу организаторов, в README датасета указаны м/с.

Выходы (издатель reliable, глубина 10; подписчик best-effort с ним совместим), все 20 Гц:

| Топик | Тип | Что внутри |
|:---|:---|:---|
| `/result/velocity` | `tram_vehicle_msgs/msg/VelocitySensor` | `velocity` - продольная скорость, м/с; `frame_id` `base_link` |
| `/result/position` | `nav_msgs/msg/Odometry` | положение, курс, скорость и их σ²; `frame_id` `map`, `child_frame_id` `base_link` |
| `/result/acceleration` | `geometry_msgs/msg/AccelStamped` | продольное ускорение модели, м/с²; `frame_id` `base_link` |
| `/tram/estimator_status` | `tram_msgs/msg/EstimatorStatus` | режим, σ скорости и пути, `valid`; `frame_id` `base_link` |

- **Поля `/result/position`.** `pose.pose.position` - x, y, z (раздел 4); `orientation` - курс;
  `pose.covariance[0]`, `[7]` - σ² положения, м²; `twist.twist.linear.x` - скорость;
  `twist.covariance[0]` - σ² скорости. Нулевых диагоналей нет
  ([ROBUST.md §4](ROBUST.md#4-ковариации-odometry)).
- **Поля `/tram/estimator_status`.** Режим (тяга, выбег, торможение, срыв, стоянка), σ скорости
  и пути, μ, `slip`, `slip_all` (+1 буксование, −1 юз), `ambiguous` («стоим или скользим»),
  `meas_noise`, принято и отвергнуто тележек, `valid`.
- **Метки времени.** `header.stamp` выходов - время из bag, а не часы ноды: сетка 50 мс по
  меткам входов, узлы кратны 0,05 с, метки монотонны.
- **Очередь подписчика - не меньше 50.** Хвост буфера в начале bag нода выдаёт пачкой, до
  49 выходов за вызов. Подписчик с глубиной 10 и медленным колбэком может часть из них потерять.
- **Паузы входов.** Если входы молчат дольше 0,1 с, нода публикует прогноз модели не дальше 0,2 с
  от последней метки (`pulse_horizon_s`), после конца bag - до 4 выходов (раздел 6).

## 6. Логи, частота, задержка, CPU и RAM

Нода пишет лог в терминал launch, копия лежит в `~/.ros/log/<дата-время>/launch.log`. Команды
ROS выполняются в любом терминале после `source ~/vectra_ws/install/setup.bash`.

Проверить, что нода видна: в списке есть `/tram_state_estimator`.

```bash
ros2 node list
```

Проверить частоту скорости: около 20 Гц (в первые секунды bag выше из-за хвоста буфера).

```bash
ros2 topic hz /result/velocity
```

Показать одно сообщение положения.

```bash
ros2 topic echo /result/position --once
```

Следить за признаком достоверности в диагностике.

```bash
ros2 topic echo /tram/estimator_status --field valid
```

Показать загрузку CPU и память процесса ноды.

```bash
top -p $(pgrep -f lib/tram_state_estimator/tram_estimator)
```

### Задержка: проба

Проба - отдельная нода с подпиской best-effort, как у проверки организаторов. Её запускают в
третьем терминале до bag; после bag и 10 с тишины она печатает итог по критериям ТЗ, полная
сводка - в JSON (`--out`).

Запустить пробу до проигрывания bag.

```bash
python3 <репозиторий>/tools/ros_probe.py --out /tmp/probe.json --idle 10
```

- **Задержка (in2out).** Время по стенным часам пробы от приёма входа `/vehicle/*` до приёма
  первого выхода со `stamp ≥ stamp` этого входа. Около 50 мс заложено схемой: показание попадает
  в следующий узел сетки 50 мс.
- **Старт bag.** Первые 2-3 с записи - хвост буфера регистратора: метки на 2-6 с старше момента
  записи приходят пачкой. Поэтому критерии задержки считаются без первых 2 с bag
  (`latency.in2out_vehicle_steady_ms` в JSON), по всей записи - строка «вместе со стартом bag»
  (`latency.in2out_vehicle_ms`). Задержка `now() − header.stamp` по `/clock` там доходит до 2,5 с:
  это свойство записи, а не ноды.
- **Справочные строки.** Две последние строки - сверка с GNSS того же bag, а не отчётная
  точность (раздел 7). Положение там сверяется с антенной master, поэтому около 10 м - плечо от
  антенны до `base_link`, а не ошибка ноды.
- **CPU и RSS.** Нужен `python3-psutil`; без него остальные метрики тоже считаются.

## 7. Точность: как посчитать самим

корня репозитория.

Посчитать точность полностью (на 4 ядрах около 6-7 мин).

```bash
docker compose run --rm eval --out out/eval_check --doc out/eval_check/EVAL.md
```

Сделать короткую проверку: 2 прогона по 300 с, около 0,5 мин.

```bash
docker compose run --rm eval --quick
```

положения - `base_link` по двум антеннам в MGRS 37UCB. Метрики по pathgraph считаются, только

## 8. Docker

Всё то же в контейнерах. Нужен Docker с Compose v2, команды выполняются из корня репозитория.

Создать `.env` из образца: папка с прогонами `DATA_DIR` и прогон `BAG` (шаг необязателен).

```bash
cp .env.example .env
```

Поднять ноду, проигрывание bag, пробу, мост и страницу симулятора.

```bash
docker compose up --build
```

Собрать пакеты и прогнать тесты без сети.

```bash
docker compose run --rm test
```

Прогнать отдельно тест времени шага.

```bash
docker compose run --rm test -m timing
```

`--build` нужен после каждого обновления исходников: нода запускается из образа. Интернет нужен
только при сборке образа (apt, pip `rosbags`), базовый образ закреплён по digest.

| Сервис | Что делает |
|:---|:---|
| `estimator` | `ros2 launch tram_state_estimator tram.launch.py` |
| `player` | ждёт ноду и пробу, затем `ros2 bag play /data/$BAG -d 5` (`PLAY_DELAY`); `PLAY_LOOP=1` - по кругу |
| `probe` | `tools/ros_probe.py`; итог - `out/probe/summary.json` |
| `bridge` | rosbridge `ws://localhost:9090`, только для чтения |
| `web` | страница симулятора `http://localhost:8080` |

### Скрипты проверки

Скрипты выполняются из корня репозитория в Git Bash или Linux. Образ по умолчанию -
`vectra/tram:compose`, если его нет, скрипт соберёт его сам. `--build` пересобирает пакеты из
рабочего дерева внутри контейнера.

Прогнать ROS-смоук на фикстуре из git, данные не нужны.

```bash
tools/ros_smoke.sh
```

Прогнать ROS-смоук на 30 с настоящего прогона из `DATA_DIR`.

```bash
tools/ros_smoke.sh --bag 30618_98161270
```

Проиграть bag целиком через ноду.

```bash
IMAGE=vectra/tram:compose tools/ros_e2e.sh --bag 30618_af7496f0 --build
```

Проверить ноду на NaN во входе.

```bash
IMAGE=vectra/tram:compose tools/ros_e2e.sh --bag 30618_bab2fe58 --inject "nan --at 15 --dur 3" --build
```

`ros_smoke.sh` проверяет: не меньше 19 Гц, in2out p99 меньше 100 мс, не меньше 95 % узлов сетки,

## 10. Если что-то не так

- **`colcon build`: `Duplicate package names`.** Два `tram_vehicle_msgs` в workspace: оставить
  наш (раздел 2).
- **`colcon build`: ошибка catkin_pkg про maintainer.** Собирается `tram_vehicle_msgs` без
  `<maintainer>`: взять наш.
- **`ros2 bag play`: не найден тип `tram_vehicle_msgs/...`.** В терминале плеера не выполнен
  `source ~/vectra_ws/install/setup.bash`.
- **Выходов нет.** Нода запущена после bag или в другом `ROS_DOMAIN_ID` / `ROS_LOCALHOST_ONLY`:
  проверить `ros2 node list`, запустить ноду раньше bag.
- **Скорость есть, `/result/position` нет.** Нода не получила GNSS master в начале bag (запущена
  поздно или в bag нет GNSS): перезапустить ноду, bag с `-d 3`.
- **x около 3 400 вместо около 103 400.** Задано `mgrs_grid: ""`: вернуть `"37UCB"`.
- **Положение около 10 м позади и на 3 м выше эталона.** Задано `output_point: master`: вернуть
  `base_link`.
- **Около 10 м в сверке пробы с GNSS.** Проба сверяет с антенной master, а выход - `base_link`;
  у `ros_smoke.sh` это строка «точность по GNSS из bag».
- **Выход 100 Гц, скорость неверная.** Задано `sheet: none` (заглушки имитатора): убрать.
- **В логе нет «карта есть».** Не найден `config/track_map.npz` в `share/tram_state_estimator`:
  пересобрать пакет. Без карты положение стоит в точке выставки (`nomap_mode: hold`).
- **Частота выше 20 Гц и задержка по `/clock` до 2,5 с в первые секунды.** Хвост буфера записи
  (раздел 6).
- **Подписчик теряет выходы на старте.** Глубина очереди меньше 50 (раздел 5).
- **Docker: порт 9090 или 8080 занят.** Задать `BRIDGE_PORT` / `WEB_PORT` в `.env`.
- **Docker: `player` пишет «bag не найден».** `DATA_DIR` - папка с каталогами прогонов, `BAG` -
  имя каталога.
- **Docker: сборка остановилась с `image … already exists`.** Compose собирал один тег
  параллельно: повторить команду или собрать без параллельного экспорта.

Собрать и поднять сервисы без параллельного экспорта образа.

```bash
COMPOSE_BAKE=false docker compose up --build
```
